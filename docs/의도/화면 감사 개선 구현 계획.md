## 2. 사용자 결정 (2026-11-26)

1. 생성 버튼: 1200px 이상에서 레일이 고정돼 있으면 비용·장수·생성을 레일 맨 아래에 둔다. 레일이 없거나 접혀 있으면 지금처럼 캔버스 아래 줄이다. `DESIGN.md`의 "One bottom action rail owns generate/cancel at every width"를 고친다.
2. 상단 메뉴: 640px 이상에서 이미지 만들기·단건 생성·씬·작업 기록을 바로 둔다. 도구 메뉴는 유틸리티를 묶음으로 나누고 단축키를 적는다.
3. 범위와 끝: P0~P2 전부와 새 기능(명령 찾기, 저장 원본 갤러리 연결)을 넣고 설치본 반영까지 한다.

## 4. 설계 원칙

- 키 입력은 안쪽이 먼저 쓴다. 안쪽(대화상자, 자동완성, 인라인 편집)이 키를 썼으면 `preventDefault`와 `stopPropagation`을 부른다. 전역 수신부의 판정은 셋이다(`resolveGlobalShortcutDisposition`). 이미 처리된 키와 입력 조합 중인 키는 건드리지 않는다. 키 반복이거나 막는 층(열린 대화상자·메뉴·선택 목록)이 있으면 실행하지 않되 브라우저 기본 동작(찾기 막대, 인쇄, 새로고침)은 막는다. 그 밖에는 실행한다. 비모달 프롬프트 시트와 프롬프트 자동완성 목록은 막는 층이 아니다. 디스패처를 새로 만들지 않고 순수 판정 함수 하나를 공유한다.
- 메인 프롬프트 표면(PromptPanel)의 고정 레일과 헤더 버튼은 `/advanced`에만 있다. 도구 메뉴의 프롬프트 항목(시트)은 `/scenes*`를 뺀 화면에서 지금처럼 열린다. `/scenes*`의 프롬프트 표면은 ScenePromptEditor 하나이고 메인 시트는 열리지 않는다.
- 보이는 생성 버튼은 언제나 하나다. 레일 자리가 준비되지 않았으면 캔버스 아래 줄이 맡는다.
- 비모달 프롬프트 시트는 Esc, 닫기 버튼, 바깥을 누를 때만 닫힌다. 메뉴나 대화상자가 닫히며 초점을 바깥 요소로 돌려주는 것으로는 닫히지 않는다.
- 내비게이션 항목은 한 곳에서 정의하고 헤더, 도구 메뉴, 명령 찾기, 단축키 순환이 함께 읽는다.
- 화면 계약이 바뀌면 `DESIGN.md`, 계약 테스트, 계약 스크립트를 같은 커밋에서 고친다. 새 문구는 `ko.json`, `en.json`, `ja.json`에 함께 넣는다.
- 새로 만드는 화면 요소는 4단계의 규칙(글자 대비 4.5:1, 아이콘 버튼과 접힘 제목 44px, 패널 외곽선 없음)을 처음부터 따른다. 전체 판정은 7단계에서 한다.

### 1단계. 키 입력 안전망 (P0-1, P1-4)

- `src/lib/keyboard/shortcut-scope.ts` 신설. 순수 함수 `shouldSkipGlobalShortcut(event, hasBlockingLayer)`와 `isEditableTarget(target)`, DOM을 읽는 `hasBlockingLayer(document)`를 둔다. 막는 층은 `[role="dialog"][data-state="open"]`, `[role="alertdialog"][data-state="open"]`, `[role="dialog"][aria-modal="true"]`(씬 상세 이미지 뷰어 `SceneDetail.tsx:1225-1231`처럼 직접 만든 창), 열린 Radix 메뉴 `[role="menu"][data-state="open"]`와 선택 목록 `[role="listbox"][data-state="open"]`이고 `data-shortcut-scope="workspace"`가 붙은 것(프롬프트 시트, 자동완성 목록)은 뺀다. Radix의 메뉴·선택 목록 항목은 `Ctrl+Enter`를 Enter로 받아 먼저 닫히므로 capture 단계에서 층 상태를 같이 기록한다.
- 전역 단축키는 `defaultPrevented`, 조합 중(`isComposing`), 키 반복(`repeat`), 막는 층이 열려 있음 가운데 하나라도 맞으면 종류(이동, 창 열기, 실행)와 상관없이 실행하지 않는다. 키 반복과 막는 층의 경우에는 `preventDefault`를 불러 WebView의 기본 동작을 막고, `/advanced` 밖의 창 열기 키도 같다(씬 상세의 조각 미리보기 `Ctrl+F`는 씬 상세가 받는다). 창은 `Esc`와 닫기 버튼으로 닫는다. 지금은 `Ctrl+G` 같은 키가 열려 있는 창을 다시 닫는데 이 동작은 없어진다.
- `useShortcuts.ts:43-70`: 바인딩을 찾은 뒤 위 판정을 거친다. 키를 누르고 있으면 생성과 취소가 번갈아 나가는 것도 `repeat`로 막힌다.
- `ThreeColumnLayout.tsx:483`: 비모달 프롬프트 시트에 `data-shortcut-scope="workspace"`.
- `PromptGeneratorDialog.tsx:233-237`: `(ctrlKey || metaKey) && key === 'Enter'`에서 `preventDefault`와 `stopPropagation`. `handleGenerate`(`:68`)에 진행 중 중복 호출을 막는 ref.
- `AutocompleteTextarea.tsx:379-405`: Enter와 Tab의 수락은 Ctrl·Cmd·Alt·Shift가 모두 없을 때만 한다. `Ctrl/Cmd+Enter`는 목록이 있든 없든 `flushPendingChange()`(`:85`)를 먼저 부르고, 목록이 떠 있으면 닫은 뒤 흘려보낸다. `Escape`는 목록이 떠 있을 때 `preventDefault`와 `stopPropagation`.

7단계 뒤의 검수에서 완료 기준에 못 미친 것과 탐침으로 찾은 결함을 고쳤다. 앞 단계의 계획과 달라진 설계만 적는다.

- 씬: `와일드카드 미리보기` 버튼은 씬 프롬프트 편집기의 도구 줄에 있고 `Ctrl+F`는 씬 상세가 받는다. 화면에 그려진 적이 없던 인스펙터 블록(캐릭터 배치, 호환용 프롬프트 칸, Resolved 버튼)은 지웠다. `/scenes` 명령 줄의 `한 번에 추가할 장수` 카운터가 카드 `+`와 `모든 씬 대기열에 추가`의 증가 폭을 정한다.
- 숫자 입력: 레일과 씬 편집기의 Steps·시드·CFG 칸은 입력 중인 글을 그대로 보여 준다(`useNumericDraft`). 그 글이 범위 안의 유효한 값이면 바로 확정해 비용과 경고가 따라오고, 빈 칸이나 범위 밖은 초점이 나가거나 Enter를 누를 때 정리한다. 비우고 나가면 초점이 들어올 때의 값이다. `Ctrl/Cmd+Enter`는 먼저 확정한 뒤 생성으로 간다.
- 폴더: 카드 안 편집기는 연 시점의 글을 기준으로 바뀌었는지 본다. 저장이 실패하면 편집기가 열린 채 다시 시도할 수 있다. 쓰기 자체가 실패했을 때만 스토어를 쓰기 직전의 글로 되돌리고, 쓰기 뒤의 확인만 실패했을 때는 되돌리지 않는다(저장됐을 수 있는 글을 옛 글로 덮지 않는다). 갤러리의 `단건 생성으로 열기`는 지금 프롬프트나 캐릭터 프롬프트가 있으면 같은 창에서 한 번 확인한다. 제목은 공용 36/30px다.
- 명령 찾기: `프롬프트 열기`는 레일을 닫지 않고 입력창에 초점을 준다. 닫으면 열기 전의 초점으로 돌아간다.
- 생성 안내: 생성 버튼, 단축키, 명령 찾기, 시트의 버튼이 낮은 Steps 차단을 같은 방식으로 알린다(`main-generation-feedback.ts`).
- 대비: 글자로 쓰는 상태색은 `--warning-text`·`--success-text`·`--info-text`를 본다. 주 버튼 안의 단축키 표기는 칩 배경이 없다.
- 설정: 단축키 덮어쓰기와 행 초기화는 같은 키를 가진 다른 동작을 지정 없음으로 비운다. `Ctrl+PageDown/Up` 순환은 메뉴 정의에서 파생한다.
- `/queue`: 작업 묶음과 legacy 대기가 모두 0이면 묶음 선택과 일시정지·재시도·취소를 그리지 않는다. 씬이 있으면 `폴더별 씬 선택`은 남는다.
- 검사: `qa:audit-regressions`가 검수 탐침을 회귀 검사 14건으로 갖고 있다. 소스를 읽는 계약 테스트는 CRLF로 풀린 작업 폴더에서도 같은 판정을 낸다.
- 헤더(릴리즈 전 보완): 영어·일본어에서는 `/advanced`의 640~680px와 768~800px에서 마지막 메뉴가 도구 버튼 위로 넘쳤다(GitHub Actions의 `test:responsive-layout`이 영어로 돌아 `main`에서 실패하던 원인). 프롬프트·기록 아이콘 버튼은 768px부터, NAI Blue 글자는 1024px부터 보이고, 메뉴 글자는 겹치기 전에 말줄임으로 줄어든다. 도구 버튼의 현재 화면 이름이 가장 먼저 줄어든다. 로컬 검사는 OS 언어(한국어)로 돌아 이 폭을 놓쳤으므로, 반응형 계약 검사가 en-US·ja-JP·ko-KR의 헤더(640·767·768·1024px)를 언어 설정과 무관하게 매번 본다. 본 검사 전체를 CI처럼 돌리려면 `RESPONSIVE_CONTRACT_LOCALE=en-US`, 러너의 넓은 기본 글꼴은 `RESPONSIVE_CONTRACT_FONT=Verdana`로 흉내 낸다.

## 7. 위험과 대비

| 위험 | 대비 |
|---|---|
| 모달 판정이 비모달 프롬프트 시트까지 막아 생성 단축키가 죽는다 | 시트에 표식을 달아 빼고, QA 스크립트에 "시트가 열린 채 `Ctrl+Enter`로 생성" 경우를 넣는다 |
| `Ctrl+Enter` 직전에 친 글자가 빠진 프롬프트로 생성된다 | 흘려보내기 전에 대기 중인 입력을 밀어 넣는다. QA 스크립트에 넣는다 |
| `/scenes*`에서 패널을 떼면 물려받는 설정, 로테이션 중지, 조각 창이 끊긴다 | 2-1에서 셋을 먼저 옮기고 마지막에 뗀다 |
| 소스 문자열을 보는 계약 테스트가 넓게 깨진다 | 단계마다 고칠 계약을 적어 두었다. 같은 커밋에서 고친다 |
| 생성 버튼이 한순간 둘이거나 없어진다 | 레일이 고정돼 보일 때만 자리를 만들고 사라질 때 비운다. 폭의 경계, 레일 접기, 시트, 모바일에서 버튼 수를 계약 스크립트로 센다 |
| 낮은 화면에서 레일이 넘친다 | 핵심 설정을 편집기와 같은 스크롤 영역에 둔다. 1280×720에서 확인한다 |
| 단축키 이전이 사용자가 바꾼 값을 덮는다 | 버전을 올려 한 번만 돌리고 옛 기본값과 같을 때만 옮긴다. 단위 테스트로 고정한다 |
| 640px 미만과 Android가 달라진다 | 그 폭의 구조는 손대지 않는다. `test:android-port`와 390×844 캡처로 확인한다 |
| 브라우저 미리보기에서는 실제 생성이 돌지 않는다 | 명령이 나갔는지까지만 자동으로 보고, 실제 생성은 설치본에서 사용자가 확인한다 |
| 폴더 양식 분리가 커진다 | 3-4의 축소안으로 넘어가고 보고에 적는다 |
