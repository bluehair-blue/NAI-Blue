# 화면 감사 개선

- 결과: 2026-11-26 UI/UX 감사(12기준 전부 미달, 이슈 13건)가 짚은 불편을 없앤다. 대화상자 안의 `Ctrl+Enter`가 뒤 화면의 유료 생성을 일으키는 오작동과 `Esc`로 씬 상세에서 튕기는 일이 사라진다. 단건 생성은 1200px 이상에서 프롬프트·핵심 설정·생성 버튼이 왼쪽 레일 한 열에 모인다. `/folders`는 첫 화면에서 바로 입력하고 카드에서 설명을 고친다. 상단 메뉴에 이미지 만들기·단건 생성·씬·작업 기록이 바로 보인다. 쓰는 사람은 사용자 본인이다.
- 완료 기준:
  1. 키 오작동 0건. AI 프롬프트 생성 창의 `Ctrl/Cmd+Enter`가 뒤 화면의 생성·취소를 부르지 않는다. 자동완성 목록이 떠 있거나 프롬프트 시트가 열려 있어도(1200px 미만) `Ctrl/Cmd+Enter`는 생성으로 가고, 직전에 친 글자가 빠지지 않는다. 씬 상세에서 자동완성 닫기, 이름 편집 취소, 대화상자 닫기의 `Esc`로 화면이 바뀌지 않는다. `npm run qa:keyboard-scope` 통과.
  2. `/scenes`와 `/scenes/:id`에 메인 프롬프트 패널이 없다. 씬 상세의 프롬프트 탭 줄은 하나이고, 두 화면 모두 채운 주 생성 버튼과 장수 카운터가 하나씩이다. 씬 상세의 주 버튼은 그 씬만 검토 창에 올린다. 물려받는 참조와 원본 이미지 설정, 로테이션 중지, 조각 미리보기가 씬 화면에서 된다.
  3. `/advanced` 1440×1000 다크: 들어가면 프롬프트 입력창이 보인다. 구현 계획 0단계의 과업 A2(입력창 누르기, 36자 입력, 설정을 눈으로 확인, 생성 누르기)를 같은 ui-capture 명령으로 재서 클릭 2회, 화면 전환과 대화상자 0회, 포인터 이동 800px 이하, KLM 15.5초 이하다. 감사와 같은 경로(A1, 기준선 7클릭·3,132px·30.51초)는 전후 값을 같이 적는다.
  4. `/folders` 1440×1000: 항목이 없을 때 첫 입력창이 y 350px 안에서 시작한다. 항목이 하나일 때 격자 보기에서 카드 전체가 보인다. 390×844에서 항목이 없을 때 `만들 이미지 추가` 버튼이 스크롤 없이 전부 보인다. 설명 한 줄 수정이 대화상자 없이 카드에서 끝난다. 선택 요약 문구는 화면에 한 곳이고, 폴더 이름은 폴더 레일과 제목 두 곳에만 나온다.
  5. 감사한 화면(`/folders`, `/advanced`, `/scenes`, `/scenes/:id`, `/queue`)의 다크와 라이트, 1440×1000과 390×844에서 글자 대비 4.5:1 미만 0건, 24×24px 미만 조작 요소 0건, 아이콘 버튼과 접힘 제목 44px 미만 0건이다(ui-capture 표 기준, 비활성 요소 제외).
  6. 640px 이상에서 상단 메뉴가 네 개이고 현재 화면이 표시된다. 도구 메뉴에 단축키가 적혀 있다. `Ctrl/Cmd+K` 명령 찾기에서 화면 이동 전부, 프롬프트·기록·내 작업 열기, 지금 화면의 주 동작, 테마 전환이 된다. 숫자 단축키 순서가 메뉴에 놓인 순서와 같다.
  7. 항목이 0건인 보조 블록이 `/folders`, `/scenes`, `/queue`, `/guided-preview`에 보이지 않는다. 작업 큐의 이름이 메뉴·제목·링크에서 하나다. `/scenes/:id`의 패널·카드 외곽선이 기준선보다 줄고 입력 칸과 행 구분선만 남는다. 저장 원본 갤러리의 이미지에서 에셋 추가와 단건 생성으로 열기가 된다.
  8. 자동 검사 통과: `lint`, `build`(tsc), `vitest run`, `test:responsive-layout`, `qa:category-design`, `qa:readable-choices`, `test:architecture`, `test:dependencies`, `test:android-port`.
  9. 새 빌드를 설치하고, 설치본에서 1·3·4의 핵심 동선을 사용자가 확인한다. `docs/README.md`의 사용본 줄이 새 해시다.
- 제약:
  - 생성 명령, 큐, 저장, MCP의 계약(서비스·도메인 층)은 그대로 둔다. 바꾸는 것은 화면, 키 입력 처리, 씬 상세 버튼이 넘기는 대상 목록이다.
  - `DESIGN.md`가 화면 계약이다. 계약과 다른 결정은 같은 커밋에서 `DESIGN.md`와 계약 검사를 함께 고친다.
  - 640px 미만과 Android의 구조(주 메뉴 2개 + 도구, 하단 실행 독)는 그대로 둔다.
  - 저장된 단축키 설정은 지우지 않는다. 옛 기본값을 그대로 쓰던 항목만 한 번 새 기본값으로 옮긴다.
  - 화면 검증은 로컬 개발 서버에 ui-capture와 Playwright로 한다. NAI Blue를 Computer Use로 조작하지 않는다(AGENTS.md). 설치는 사용자가 실행한다.
- 하지 않는 것: 릴리즈(원격 push, 태그, 버전 올리기). 감사하지 않은 화면(`/tools`, `/style-lab`, `/library`, `/settings`, `/data`, `/r2`, `/web`, `/trash`)의 재설계 — 공용 부품이 바뀌어 따라 달라지는 것만 확인한다. 키 입력을 한곳에서 나눠 주는 디스패처 신설. 실제 사용자 사용성 시험.
- 미정:
  - 범주 제목 크기는 36/30px를 유지한다(전 범주 공용 단계). 3단계 재측정에서 완료 기준 4를 못 채우면 전 범주 제목을 함께 줄인다.
  - 숫자 단축키 새 기본값: `Ctrl+1` 이미지 만들기, `2` 단건 생성, `3` 씬, `4` 작업 기록, `5` 스마트 툴, `6` 라이브러리, `7` 웹, `8` 설정.
  - 열려 있는 창을 같은 단축키로 닫는 동작(`Ctrl+G` 등)은 없앤다. 창은 `Esc`와 닫기 버튼으로 닫는다.
  - 작업 큐 이름은 "작업 기록"으로 통일한다(ko). en·ja는 같은 뜻의 기존 낱말로 맞춘다.
  - 레일 폭은 1200~1535px에서 360px, 1536px부터 420px, 1800px부터 500px.
  - 큐 실행 권한이 legacy일 때 씬 상세 버튼은 지금처럼 대기열 전체를 실행한다(레거시 실행기는 대상을 고르지 못한다).
  - 설치본은 버전 번호를 올리지 않은 로컬 빌드다(해시로 구분). 번호는 릴리즈 때 정한다.
  - 작업 브랜치는 지금의 `codex/startup-responsiveness`.
- 출발점: 단계, 파일, 줄 번호, 재검토 결과는 [구현 계획](화면%20감사%20개선%20구현%20계획.md). 화면 계약은 `DESIGN.md`. 계약 검사는 `scripts/verify-responsive-layout-contract.mjs`와 `tests/components/*.contract.test.ts`. 감사 원문은 2026-11-26 대화에만 있고 캡처는 지워졌으므로 0단계에서 기준선을 다시 뽑는다.
- 기준 커밋: `7d42725` (v1.4.0)
