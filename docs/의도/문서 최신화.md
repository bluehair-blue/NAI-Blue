# 문서 최신화

- 결과: README 세 언어와 `docs/`가 지금의 NAI Blue(작업대 중심의 데스크톱·Android 앱)를 설명한다. NAIS2 계승 서술, 옛 Guided 흐름, phase·인수인계 기록이 빠져서 처음 보는 사람이 현재 제품으로 읽는다. 읽는 사람은 GitHub 방문자와 이 저장소에서 일하는 에이전트다.
- 완료 기준:
  1. `README.md`·`README.ko.md`·`README.ja.md`가 같은 구조(소개, 하는 일, 설치, 처음 쓰기, 소스 빌드, 제보, 크레딧)이고, 본문의 화면·메뉴 이름이 `src/i18n/locales/`의 현재 문자열과 일치한다.
  2. 각 README에 그 언어 화면의 캡처 2~3장이 들어 있다.
  3. NAIS2는 README마다 크레딧 한 줄과 메타데이터 가져오기 호환 한 구절에만 나온다.
  4. `docs/`에는 ADR 20개, 영속화 지도, V5·프롬프트 리서치, 의도 문서, 코드가 참조하는 벤치마크 JSON만 남는다. `docs/README.md`는 한 화면 분량의 인덱스다.
  5. `RELEASING.md`가 지금의 릴리즈 절차(태그, Android 승인, versionCode)와 맞다.
  6. 저장소 안 문서 링크가 모두 살아 있고 자동 검사가 통과한다.
  7. GitHub 저장소 소개 문구·토픽의 새 문안과 push 명령을 사용자에게 건넨다(실행은 사용자).
- 제약: 소스 코드와 앱 안 문구는 바꾸지 않는다(가져오기 호환 식별자 포함). GPL-3.0 라이선스와 NovelAI 비제휴 고지는 유지한다. 캡처에는 실제 계정·프롬프트·생성 이미지가 들어가지 않게 데모 데이터를 쓴다. 내리는 파일은 Git 이력에 남긴다.
- 하지 않는 것: 앱 화면 변경, ADR 본문 재작성(내린 파일을 가리키는 링크만 고친다), `AGENTS.md`의 작업 규칙 변경, 위키·웹사이트 신설.
- 내리는 파일(28개): `docs/releases/`의 인수인계·릴리즈 기록 3개(`v1.0.0-handoff.md`, `시작 응답성.md`, `저장 이미지 폴더 탐색.md`)와 `evidence/`의 검증 JSON 21개(`queue-edge-benchmark.json`은 남긴다), `docs/architecture/phase-0-baseline.md`, `docs/research/2026-10-31-ui-performance-*` 3개.
