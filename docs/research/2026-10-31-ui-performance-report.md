# NAI Blue 성능·생성 모니터 수정 결과

반복 처리를 줄이고 공통 생성 모니터와 저장 폴더 목록을 추가해 Windows 앱에 적용했습니다. 구현은 4개 커밋으로 나눠 기록했습니다.

- 화면 갱신: 스크롤·진행 표시마다 전체 장면과 이력을 직렬화하던 작업을 줄였습니다. 넓은 상태 구독, 드래그 위치 측정, 시작 시 중복 복구도 정리했습니다.
- 생성 모니터: 등록된 에이전트들이 공유하는 Queue에 생성 상태와 프리뷰를 연결했습니다. 어느 화면에서든 상단 모니터를 보고, 프리뷰를 누르면 현재 편집 화면을 유지한 채 크게 볼 수 있습니다.
- 저장 폴더: 왼쪽의 저장 이미지 폴더 목록에 Artifact와 기존 장면 이미지의 저장 경로를 모읍니다. 새 저장 이벤트를 반영하며 폴더별 이미지를 볼 수 있습니다.

관련 테스트, TypeScript, 의존성 검사와 Windows 빌드를 통과했습니다. 최종 앱 재시작 후 공식 MCP 응답과 기존 프리셋 297개·장면 3,138개 보존을 확인했습니다.

실제 스크롤 FPS와 새 유료 이미지 생성은 검증하지 않았습니다. 생성 중 이미지 프리뷰는 Provider가 중간 프레임을 제공하는 경우 표시됩니다.

## 조사와 수정 범위

공통 레이아웃, Scene·Library·History·원본 이미지·도구 대화상자, Scene authority, 생성 이력 저장, 에이전트 작업 공간 동기화, Main/Scene Queue 실행 경로, 결과 저장 이벤트, 왼쪽 폴더 탐색과 시작 복구를 확인했습니다.

전체 장면 직렬화는 실제로 바뀐 프리셋만 처리하도록 바꿨습니다. 영속 필드가 같으면 이력 JSON 재생성과 저장을 건너뜁니다. Library의 상시 드래그 측정을 제거하고 이미지 지연 로딩·비동기 디코딩을 적용했습니다.

프리뷰는 작업별 메모리에만 보관하고 종료 때 해제합니다. 첫 프레임은 즉시, 이어지는 프레임은 최대 200ms 간격으로 최신 한 장만 표시합니다. 상단에는 진행 카드 4개와 최근 결과 4개를 표시하고 추가 작업은 활동 목록으로 연결합니다. Scene 경로에서 버려지던 Provider 프레임도 전달합니다.

저장 폴더는 실제 파일 이동 없이 메타데이터로 표시합니다. 최초 한 번 128개 단위로 읽고, 경로 해석 동시 실행은 8개로 제한합니다. 이후 저장 이벤트로 갱신합니다. 폴더는 40개, 갤러리는 60개 단위로 표시합니다. 기존 저장 정책·설정 폴더·승인·원본 파일은 변경하지 않았습니다.

시작 복구는 이미 연결된 Artifact를 일괄 문서에서 확인하고 각 프리셋의 최신 문서를 한 번만 화면에 적용합니다. 누락 연결은 기존 최신 문서 읽기와 충돌 검사를 유지합니다.

테스트 묶음에는 중복이 있어 통과 수를 합산하지 않았습니다. 실제 Provider 대신 콜백과 Queue 수명 주기를 검증했고, 동시 작업 분리·프레임 정리·저장 이벤트·경로 중복 제거·재시도를 포함합니다.

최종 공식 응답은 `perf-visibility-postrestart-20261031-06`이며 기존 작업 공간, 프리셋 297개, 장면 3,138개, 설정 폴더 3개, 초안 4개가 유지됐습니다. 생성·대기 작업은 0개였고 기존 확인 필요 작업 8개는 그대로 보존했습니다. 새 결과 목록은 설정 폴더 개수와 별개입니다.

## 남은 사항과 제외 사유

실제 화면의 FPS·입력 지연은 측정하지 않아 모든 렉이 해결됐다고 단정하지 않습니다. 새 유료 Provider 생성은 수행하지 않았으며 실제 중간 프리뷰는 스트리밍 지원에 따릅니다. 지원하지 않는 경로는 진행 상태와 저장 완료 결과를 표시합니다.

보관 중인 Provider 결과 2,356개(약 1.49GB)의 무결성 확인은 데이터 복구 안전성 때문에 유지했습니다. 최종 시작부터 공식 응답까지 약 114초가 관찰됐으며 통제된 속도 비교는 아닙니다. 백그라운드 무결성·백업 단계 완료도 확인했습니다.

Codex의 공식 `open_in_codex`는 네이티브 Windows 창을 임베드하는 유형을 제공하지 않습니다. 실제 NAI Blue는 Windows에 실행해 두고 오른쪽 패널에는 이 검증 기록을 요청했습니다. 공식 도구는 현재 채팅이 숨겨진 경우의 `queued` 상태를 반환했습니다. 채팅을 다시 표시할 때 열리도록 대기 중이며, 측면 패널의 실제 표시 성공은 확인하지 못했습니다. NAI Blue에 CUA·CDP·브라우저 자동화는 사용하지 않았습니다.

초기 Gemini·Claude 설계 협의는 완료했습니다. 최종 Gemini 문장 편집은 HTTP 200 스트림 응답 읽기 오류로 실패했습니다. 진단 후 축약 요청으로 재연결했지만 같은 오류가 발생해 이 보고서는 GPT가 검증 사실로 작성했습니다. 앱 연결은 별도로 정상 확인됐습니다.
