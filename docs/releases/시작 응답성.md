## 변경

- 완료된 Composition 마이그레이션은 현재 원본 해시·저장소 해시·참조·재조회 결과를 검증한다. 변경이 없으면 복구 아카이브와 변환 결과를 다시 만들지 않는다. 원본 변경·손상·미완료 상태에는 기존 절차를 적용한다.
- 실제 마이그레이션은 Worker가 IndexedDB·검증·CAS·롤백을 담당한다. 파일 권한이 필요한 작업만 기존 네이티브 경로에 전달하며 실패 시 자동 재실행하지 않는다.
- 저장소 존재 확인은 키 목록만 읽는다. 로컬 저장소 복사와 이름 변경의 모든 진입점에서 대용량 백업 값을 불필요하게 읽지 않는다. 새로 복사한 값은 기존처럼 정확한 readback을 확인한다.
- Scene 화면 준비·최초 변경 확인·Queue 이력 검증은 약 8ms씩 나누어 입력 처리 기회를 준다. Queue의 job·lease는 같은 읽기 트랜잭션에서 가져오고, 검증만 트랜잭션 종료 후 분할한다.
- 저장 이미지 1,258개의 파일 확인은 작은 병렬 묶음으로 진행한다. 같은 생성 당시 폴더의 경로 해석은 재사용하지만 파일 존재 여부는 각각 확인한다.
- 시작 단계 기록의 파일 쓰기를 직렬화하고, 50ms 타이머 및 Long Task 계측으로 첫 구간과 복구 구간을 따로 측정한다.
- 앞선 개선의 백업 Worker·대용량 JSON 스트리밍·실행 이력 검증 Worker·Windows 기본 창 버튼을 유지한다.
